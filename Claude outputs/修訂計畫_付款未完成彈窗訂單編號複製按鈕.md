# 修訂計畫：付款未完成彈窗 — 訂單編號複製按鈕

## 1. 目的

在「付款未完成」畫面（`#payFailedView`）中，使用者需要手動抄寫訂單編號以聯絡客服或重新查詢交易，容易抄錯。在訂單編號旁加上一個小型複製按鈕，點擊即可將編號複製到剪貼簿，並以 Toast 提示複製成功。

## 2. 現況（相關程式碼位置）

專案：`蟑螂`（Scholar Coach），Demo 模擬付款流程。

- **HTML**：`index.html` 第 637–653 行，`#payFailedView`
  - 訂單編號目前位置：第 644 行
    ```html
    <div class="pay-result-meta">訂單編號：<span id="payFailedOrderNo">--</span></div>
    ```
- **JS**：`js/ui/Member.js`
  - `showPaymentFailed()`（第 325–331 行）：畫面顯示時，將 `currentTransaction.orderNo` 寫入 `#payFailedOrderNo`。
  - 專案已有 `showToast(message, type, duration)` 工具（`js/utils/Toast.js`），可直接沿用做複製成功提示。
- **CSS**：`css/main.css`
  - `.pay-result-meta`（第 2368–2378 行）：目前僅為文字樣式，無按鈕。
  - 專案內已有一個 `.copy-btn` class（第 1302–1323 行），但屬於較大的文字按鈕（padding 8px 16px），目前沒有任何地方在使用，樣式尺寸不適合放在訂單編號這種行內小面積，需另外設計小型 icon 按鈕，不沿用此 class（避免與既有未使用樣式衝突）。

**範圍確認**：「訂單編號」在付款彈窗的 3 個子畫面（確認訂單 `paySummaryView`、處理中 `payProcessingView`、未完成 `payFailedView`）都有出現，本次僅修改 **`payFailedView`**，其餘兩個畫面不動。

**複製成功回饋方式**：採用跳出 Toast 提示（沿用既有 `showToast()`），不做按鈕圖示變勾勾的動畫。

## 3. UI 設計

- 位置：緊接在 `<span id="payFailedOrderNo">` 右側，同一行內。
- 樣式：小型 icon-only 按鈕（建議 20×20px 可點擊區域），使用專案已載入的 Font Awesome（`fa-copy` / `fa-regular fa-copy`），預設為淡灰色，hover 時變深色 + 淺底色，符合 `.pay-result-meta` 目前的低調配色（`#94a3b8` / `#475569`）。
- 不額外顯示文字「複製」，維持精簡；可加 `title="複製訂單編號"` 提供 tooltip 與無障礙支援。

### 4.3 JS（`js/ui/Member.js`）

在檔案頂部加入複製工具函式，並於 `showPaymentFailed()` 內綁定點擊事件（因該畫面每次顯示都會呼叫此函式，適合在此處做事件綁定，避免額外在 `initPaymentEvents()` 增加初始化時序相依）：

```js
import { showToast } from '../utils/Toast.js';

// 複製文字到剪貼簿，含降級處理（非 HTTPS 或不支援 Clipboard API 時）
async function copyText(text) {
  if (navigator.clipboard && window.isSecureContext) {
    await navigator.clipboard.writeText(text);
    return;
  }
  // 降級方案
  const textarea = document.createElement('textarea');
  textarea.value = text;
  textarea.style.position = 'fixed';
  textarea.style.opacity = '0';
  document.body.appendChild(textarea);
  textarea.select();
  document.execCommand('copy');
  document.body.removeChild(textarea);
}

export function showPaymentFailed() {
  const orderNoEl = document.getElementById('payFailedOrderNo');
  if (orderNoEl && currentTransaction.orderNo) {
    orderNoEl.textContent = currentTransaction.orderNo;
  }
  showPayView('payFailedView');

  const copyBtn = document.getElementById('payFailedOrderCopyBtn');
  if (copyBtn) {
    copyBtn.onclick = async () => {
      if (!currentTransaction.orderNo) return;
      try {
        await copyText(currentTransaction.orderNo);
        showToast('已複製訂單編號', 'success', 2000);
      } catch (err) {
        showToast('複製失敗，請手動選取複製', 'error', 3000);
      }
    };
  }
}
```

> 註：目前 `showPaymentFailed()` 只由 Demo 面板呼叫觸發付款失敗畫面；正式串接金流失敗回調後，此函式仍會是失敗畫面的統一進入點，複製按鈕邏輯不需額外調整。

## 5. 邊界情況

- `currentTransaction.orderNo` 為空字串時（理論上不應發生，但作防呆）：不執行複製、不跳 Toast。
- 非 HTTPS 環境或瀏覽器不支援 `navigator.clipboard`：走 `document.execCommand('copy')` 降級方案。
- 複製失敗（例外拋出）：跳出錯誤提示 Toast，不影響使用者返回上一步或重新付款的操作。

## 6. 驗收標準

1. 開啟付款未完成畫面（可透過 Demo 面板觸發），訂單編號旁出現一個小型複製 icon 按鈕。
2. 點擊按鈕後，剪貼簿內容為畫面顯示的完整訂單編號（貼上驗證）。
3. 點擊後跳出「已複製訂單編號」成功提示（Toast，綠色 success 樣式）。
4. 按鈕不影響「重新付款」「返回上一步」「聯絡客服」等既有互動與版面排版。
5. 確認訂單畫面（`paySummaryView`）與付款處理中畫面（`payProcessingView`）維持原樣，未被誤動。
